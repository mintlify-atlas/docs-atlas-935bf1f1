The mthcht/awesome-lists repository is a curated collection of structured detection data, rule repositories, and testing frameworks designed to accelerate SOC operations and detection engineering workflows.

## How this collection supports your SOC

Whether you are writing new detections, tuning existing alerts, or validating coverage against real-world adversary techniques, this collection provides the raw material at every step. The lists are maintained as CSV files with rich metadata columns, making them directly importable into any SIEM as lookup tables or reference data.

## MITRE ATT&CK integration

Every list in this collection maps detections back to the MITRE ATT&CK framework. The `metadata_tactic` and technique columns in the CSV files let you filter detections by ATT&CK tactic and measure your coverage programmatically.

## Purple Team and detection validation

Detections are only valuable if they fire when expected. The [PurpleTeam scripts](https://github.com/mthcht/Purpleteam) and [Atomic Red Team](https://github.com/redcanaryco/atomic-red-team) atomics allow you to simulate the exact adversary behaviors that the lists are designed to detect.

<Steps>
  <Step title="Pick a detection list">
    Choose a list such as `suspicious_named_pipe_list.csv` or `suspicious_windows_services_names_list.csv` and ingest it as a SIEM lookup table.
  </Step>
  <Step title="Write or import a detection rule">
    Use the corresponding Sigma rule or SPL query to alert when an event matches a value in the list. See [SIEM & Detection Rules](/soc/siem-and-rules) for platform-specific examples.
  </Step>
  <Step title="Simulate the technique">
    Run the matching Atomic Red Team test or PurpleTeam script on a test endpoint to generate the expected telemetry.
  </Step>
  <Step title="Validate the alert">
    Confirm the SIEM alert fires, then tune severity and false-positive filters using the `metadata_fp_risk` and `metadata_severity` columns in the CSV.
  </Step>
</Steps>

<Tip>
  Use the [EDR Telemetry project](https://github.com/tsale/EDR-Telemetry) to understand which events your EDR actually surfaces before writing detections that depend on specific log sources.
</Tip>
